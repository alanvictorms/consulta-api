Começando

A API permite consultar os módulos disponíveis no plano por meio de requisições autenticadas. Siga esta ordem para sua primeira integração.

  1. Gere uma API KeyObtenha uma chave pelo Painel API e guarde-a em local seguro.
  2. Escolha o móduloConsulte o catálogo para obter ID e parâmetros necessários.
  3. Envie a requisiçãoFaça um POST para /api/v1/query com JSON no corpo.
  4. Leia os dadosConfira success, data e meta no retorno.

                AUTENTICAÇÃO
                
Autenticação e chaves

                
Cada requisição deve conter uma credencial válida. O cabeçalho recomendado é X-API-Key. Também há suporte a Bearer Token como alternativa.

                

                    

                        
HeaderValorUso

                        
                            
X-API-KeySUA_CHAVERecomendado

                            
AuthorizationBearer SUA_CHAVEAlternativo

                            
Content-Typeapplication/jsonCorpo da requisição

                        
                    

                

                
Nunca exponha a chave no JavaScript público do navegador. Faça requisições autenticadas a partir de um backend seguro.

            


            

                AUTENTICAÇÃO
                
Gerenciamento de chaves

                
Crie chaves no Painel API. Para substituir uma credencial, gere outra, atualize sua aplicação e só então revogue a antiga.

                

                    
CriarPainel API, Chaves de acesso, Gerar nova chave.

                    
RotacionarAtive a nova chave em seus serviços antes de revogar a antiga.

                    
ArmazenarMantenha credenciais em variáveis de ambiente do backend, nunca no frontend.

                API REFERENCE
                
Endpoint de consulta

                
Todas as consultas são enviadas para o mesmo endpoint. O campo module identifica o recurso e os demais campos variam de acordo com o módulo.

                
POST/api/v1/query

                
Corpo JSON

                

                    

                        Exemplo de consulta
                        
                    

                    
{
  "module": "cb_cpf",
  "cpf": "00000000000"
}

                

                
O CPF é apenas um valor fictício de exemplo, não um registro consultado.

            


            

                API REFERENCE
                
Formato de resposta e JSON Schema

                
O envelope de retorno utiliza os campos success, data e meta. success é booleano; meta.time_ms é inteiro; meta.module é string. data é conteúdo JSON variável devolvido pelo serviço de origem (o objeto vazio {} é um marcador didático, não uma amostra real ou garantia de retorno vazio).

                

                    

                        Envelope de resposta implementado · 200
                        
                    

                    
{
  "success": true,
  "data": {},
  "meta": {
    "time_ms": 234,
    "module": "ID_DO_MODULO"
  }
}

                

                

                    
success
boolean — Indica se a chamada ao módulo foi concluída com sucesso

                    
data
object | array — Conteúdo JSON variável devolvido pelo serviço de origem

                    
meta.time_ms
integer — Tempo de execução em milissegundos

                    
meta.module
string — Identificador do módulo executado

                

                

                    

                        JSON Schema do Envelope
                        
                    

                    
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "required": ["success", "data", "meta"],
  "properties": {
    "success": { "type": "boolean" },
    "data": { "type": ["object", "array", "null"] },
    "meta": {
      "type": "object",
      "required": ["time_ms", "module"],
      "properties": {
        "time_ms": { "type": "integer" },
        "module": { "type": "string" }
      }
    }
  }
}

                

                

                    Limitação de schema dos provedores: A aplicação não normaliza os campos internos de data nem mantém um schema validado por módulo. A documentação descreve o envelope efetivamente implementado e explicita essa variabilidade.

                INTEGRAÇÃO
                
Dicas de integração

                

                    
Repetição controladaPara erro temporário 503, aguarde 2 segundos antes de tentar novamente, com máximo de 3 tentativas.

                    
TimeoutRecomendamos 30 segundos de timeout; consultas complexas (como CNPJ + Titular) podem demorar até 20 segundos.

                    
CacheEvite repetir consultas idênticas desnecessariamente; considere cache com validade adequada ao dado.

                

            


            

                REFERÊNCIA
                
Erros e respostas HTTP

                
Quando uma chamada falha, o retorno contém um objeto JSON com error e code:

                

                    
Estrutura de Erro

                    
{
  "error": "Parâmetros obrigatórios: cpf",
  "code": "MISSING_PARAMS"
}

Requisição inválida
MISSING_MODULE, INVALID_MODULE, MISSING_PARAMS

                
401
Sem autorização
UNAUTHORIZED

                
403
Sem permissão
FORBIDDEN

                
429
Limite de uso
RATE_LIMITED

                
500
Erro no servidor
INTERNAL_ERROR

                
503
Serviço indisponível
SERVICE_UNAVAILABLE

            


            

                BOAS PRÁTICAS
                
Tratamento de erros

                
Valide parâmetros antes do envio, mantenha as credenciais no backend e trate respostas HTTP inesperadas. Em instabilidades temporárias, implemente novas tentativas com intervalo progressivo, evitando repetição imediata.

                
Se o erro for de autenticação, permissão ou parâmetros, corrija a causa antes de tentar novamente. Para respostas com limite de uso, respeite a janela definida pelo servidor.
